Как работают прямые эфиры на YouTube, TikTok Live или Twitch? Для них используется технология прямой потоковой передачи — live streaming.

В отличие от обычной потоковой передачи, видеоконтент отправляется через интернет в реальном времени, обычно с задержкой всего в несколько секунд.

Схема показывает, какие процессы делают это возможным.

## Этапы прямой трансляции

**Шаг 1:** камера и микрофон захватывают исходные видео- и аудиоданные. Они отправляются на сервер.

**Шаг 2:** видеоданные сжимаются и кодируются. Например, алгоритм сжатия может отдельно обрабатывать фон и другие элементы изображения. После сжатия видео кодируется по стандарту, например H.264. Размер данных на этом этапе существенно уменьшается.

**Шаг 3:** закодированные данные разделяются на небольшие сегменты, обычно длительностью в несколько секунд. Это ускоряет их загрузку и потоковую передачу.

**Шаг 4:** сегменты отправляются на сервер трансляции. Он должен поддерживать разные устройства и условия сети. Для этого применяется адаптивная передача с изменяемым битрейтом: на шагах 2 и 3 создаются несколько версий файлов с разным битрейтом.

**Шаг 5:** данные прямой трансляции передаются на периферийные серверы CDN (сети доставки контента). Миллионы зрителей могут получать видео с ближайшего сервера. CDN значительно снижает задержку передачи данных.

**Шаг 6:** устройство зрителя декодирует и распаковывает видеоданные, а затем воспроизводит видео в плеере.

**Шаги 7 и 8:** если трансляцию нужно сохранить для повторного просмотра, закодированные данные отправляются на сервер хранения. Позже зритель может запросить запись с этого сервера.

## Стандартные протоколы прямых трансляций

Для прямых трансляций используются следующие протоколы:

* **RTMP (Real-Time Messaging Protocol):** первоначально разработан Macromedia для обмена данными между Flash-плеером и сервером. Теперь используется для потоковой передачи видео через интернет. Приложения видеоконференций, например Skype, применяют RTC (Real-Time Communication), чтобы уменьшить задержку.
* **HLS (HTTP Live Streaming):** требует кодирования H.264 или H.265. В исходном материале для устройств Apple указан только формат HLS.
* **DASH (Dynamic Adaptive Streaming over HTTP):** в исходном материале указано отсутствие поддержки устройств Apple.

HLS и DASH поддерживают адаптивную потоковую передачу с изменяемым битрейтом.
