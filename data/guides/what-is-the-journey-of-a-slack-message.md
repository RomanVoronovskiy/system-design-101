В одной из последних технических статей Slack объясняет, как работает его система обмена сообщениями в реальном времени. Вот мое краткое резюме:

Слак-сообщение проходит через пять важных серверов:

*   **Веб-апп:** определяет API, который может использовать клиент Slack
*   **Административный сервер (АС):** найти правильный сервер канала с помощью идентификатора канала
*   **Сервер канала (CS):** :: поддерживает историю канала сообщений
*   **Сервер врат (ОО):** :: развернуты в каждом географическом регионе. Поддерживать подписку на канал WebSocket
*   **Посланник:** Опосредованный показатель услуг для применения в облачных условиях

*   Поскольку имеется слишком много каналов, сервер канала (CS) использует последовательный хешинг, чтобы выделить миллионы каналов многим серверам канала.
*   Слать сообщения доставляются через веб-апп и админ сервер на правильный сервер канала.
*   Через сервер и посланник (посредник) Gate Server будет перекладывать сообщения на приемники сообщений.
*   Приемники сообщений используют веб-Socket, который является механизмом обмена сообщениями с двусторонним направлением, и они могут получать обновления в реальном времени.
