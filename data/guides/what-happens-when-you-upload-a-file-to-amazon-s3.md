Прежде чем рассматривать архитектуру, определим основные термины.

**Бакет (Bucket)** — логический контейнер для объектов. Его имя глобально уникально. Для загрузки данных в S3 сначала нужно создать бакет.

**Объект (Object)** — отдельная единица данных, хранящаяся в бакете. Он содержит собственно данные — полезную нагрузку — и метаданные. Данные могут быть любой последовательностью байтов. Метаданные — набор пар «имя — значение», описывающих объект.

Объект S3 состоит из двух частей, показанных на рисунке 1:

* **Метаданные:** изменяемые атрибуты, например идентификатор, имя бакета и имя объекта.
* **Данные объекта:** неизменяемое содержимое.

Объект находится внутри бакета. Путь может выглядеть так: /bucket-to-share/script.txt. Бакет содержит только метаданные, а объект — метаданные и само содержимое.

На рисунке 2 показана загрузка файла. Сначала создаётся бакет bucket-to-share, затем в него загружается script.txt.

1. Клиент отправляет HTTP PUT для создания бакета bucket-to-share. Запрос поступает в API-сервис.
2. API-сервис обращается к Identity and Access Management (IAM), чтобы убедиться, что пользователь авторизован и имеет разрешение WRITE.
3. API-сервис поручает хранилищу метаданных создать запись о бакете. После её создания клиент получает сообщение об успехе.
4. Клиент отправляет следующий HTTP PUT — для создания объекта script.txt.
5. API-сервис проверяет личность пользователя и наличие разрешения WRITE для бакета.
6. После успешной проверки содержимое HTTP PUT передаётся в хранилище данных. Оно сохраняет полезную нагрузку как объект и возвращает его UUID.
7. API-сервис создаёт запись в базе метаданных. В ней содержатся object_id (UUID), bucket_id, указывающий бакет объекта, object_name и другие важные атрибуты.
