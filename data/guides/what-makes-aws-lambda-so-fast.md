В основе производительности лежат четыре ключевых компонента.

## Вызов функции

AWS Lambda поддерживает синхронные и асинхронные вызовы.

При синхронном вызове клиент напрямую обращается к функции через AWS CLI, SDK или другие сервисы.

При асинхронном вызове клиент не ждёт ответа функции. После авторизации запроса событие помещается во внутреннюю очередь SQS. Компоненты опроса читают сообщения и передают их на обработку.

## Assignment Service

Сервис назначения управляет средами выполнения.

Для высокой производительности он написан на Rust. Сервис разделён на несколько секций, а схема «лидер — последователи» обеспечивает высокую доступность.

Состояние сред выполнения записывается во внешний журнал.

## Микровиртуальные машины Firecracker

Firecracker — легковесный менеджер виртуальных машин для бессерверных нагрузок, включая AWS Lambda и AWS Fargate.

Он использует KVM в ядре Linux для создания и управления защищёнными микровиртуальными машинами с быстрым запуском.

## Хранение компонентов

AWS Lambda также управляет состоянием, включающим входные данные и код функции.

Для эффективности применяются несколько подходов:

* Разбиение образов контейнеров на блоки для более эффективного хранения.
* Конвергентное шифрование общих данных. Дополнительные данные присоединяются к блоку для вычисления более устойчивого хеша.
* SnapStart предварительно инициализирует среду выполнения и сокращает задержку холодного запуска.
