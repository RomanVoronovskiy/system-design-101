На схеме показаны четыре способа предоставить доступ к сервису.

В Kubernetes Service позволяет предоставить сетевой доступ к приложению в кластере. Сервис делает набор подов доступным по сети, чтобы с ним могли взаимодействовать пользователи.

Существуют четыре типа сервисов: ClusterIP, NodePort, LoadBalancer и ExternalName. Свойство type в спецификации Service определяет способ предоставления доступа по сети.

## Типы сервисов Kubernetes

* **ClusterIP**

  Это тип по умолчанию и наиболее распространённый вариант. Kubernetes назначает сервису внутренний IP-адрес кластера. Обратиться к нему можно только изнутри кластера.

* **NodePort**

  Сервис становится доступен извне кластера: поверх ClusterIP добавляется порт на узлах кластера. Обратиться к сервису можно по адресу NodeIP:NodePort.

* **LoadBalancer**

  Предоставляет внешний доступ к сервису через балансировщик нагрузки облачного провайдера.

* **ExternalName**

  Сопоставляет сервис с доменным именем. Часто используется, чтобы представить внешнюю базу данных как сервис внутри Kubernetes.
