Как бы банально это ни звучало, небольшие изменения действительно могут давать большой эффект.

Команда повышения продуктивности разработки Pinterest убедилась в этом на собственном опыте.

Она внесла небольшое изменение в конвейер сборки Jenkins для монорепозитория Pinboard.

В результате время клонирования сократилось с 40 минут до впечатляющих 30 секунд.

Pinboard — самый старый и самый большой монорепозиторий Pinterest. Несколько фактов о нём:

* **350 тысяч коммитов**
* **20 ГБ при полном клонировании**
* **60 тысяч операций git pull каждый рабочий день**

Клонирование монорепозиториев с большим объёмом кода и длинной историей занимает много времени. Именно с этим столкнулась команда Pinboard.

Конвейер сборки, написанный на Groovy, начинался с этапа Checkout: репозиторий клонировался для последующей сборки и тестирования.

В настройках уже были включены поверхностное клонирование, отключение загрузки тегов и получение только последних 50 коммитов.

Однако одну важную оптимизацию упустили.

Этап Checkout не использовал параметр Git refspec.

В итоге при каждой сборке Git фактически получал все ссылки. В случае Pinboard это означало загрузку более 2500 веток.

**Что же исправили?**

Команда добавила параметр refspec и указала нужную ссылку — в данном случае ветку master.

Благодаря этому Git стал клонировать только одну ветку, что значительно сократило общее время сборки монорепозитория.
