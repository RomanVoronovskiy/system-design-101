Какую базу данных мне следует использовать для **системы сбора показателей**? Это один из самых важных вопросов, которые нам необходимо ответить на собеседовании по проектированию системы.

## Шаблон доступа к данным

Как показано на диаграмме, каждая метка на оси Y представляет временной ряд (уникально идентифицируемый именами и метками), а ось X представляет время.

Нагрузка на запись большая. Как видите, в любой момент может быть записано множество точек данных временных рядов. Ежедневно записываются миллионы операционных метрик, и многие метрики собираются с высокой частотой, поэтому трафик, несомненно, требует больших объемов записи.

В то же время нагрузка на чтение очень высока. Службы визуализации и оповещений отправляют запросы в базу данных, и в зависимости от шаблонов доступа к графикам и оповещениям объем чтения может быть скачкообразным.

## Выберите правильную базу данных

Система хранения данных является сердцем конструкции. Не рекомендуется создавать собственную систему хранения или использовать для этой работы систему хранения общего назначения (MySQL).

База данных общего назначения теоретически могла бы поддерживать данные временных рядов, но для ее работы в нашем масштабе потребуется настройка на экспертном уровне. В частности, реляционная база данных не оптимизирована для операций, которые вы обычно выполняете с данными временных рядов. Например, вычисление скользящего среднего в скользящем временном окне требует сложного SQL, который трудно читать (пример этого есть в разделе углубленного изучения). Кроме того, для поддержки данных тегирования/маркировки нам необходимо добавить индекс для каждого тега. Более того, реляционная база данных общего назначения плохо работает при постоянной большой нагрузке на запись. В нашем масштабе нам придется приложить значительные усилия для настройки базы данных, и даже в этом случае она может работать неэффективно.

Как насчет NoSQL? Теоретически, несколько баз данных NoSQL на рынке могут эффективно обрабатывать данные временных рядов. Например, Cassandra и Bigtable можно использовать для данных временных рядов. Однако для разработки масштабируемой схемы эффективного хранения и запроса данных временных рядов потребуются глубокие знания внутренней работы каждого NoSQL. Поскольку базы данных временных рядов промышленного масштаба легко доступны, использование базы данных NoSQL общего назначения не является привлекательным.
