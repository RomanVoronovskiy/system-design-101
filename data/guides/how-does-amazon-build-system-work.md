Познакомимся с системой сборки Amazon — Brazil.

В модели ответственности Amazon каждая команда управляет собственными репозиториями, что помогает быстрее внедрять изменения. Для повышения продуктивности и совместной работы в такой структуре Amazon создала систему сборки Brazil. Рассмотрим её подробнее.

С Brazil разработчик может сосредоточиться на коде и подготовить понятный файл конфигурации сборки. Система затем воспроизводимо создаёт выходной артефакт. В конфигурации кратко задаются необходимые параметры: язык, версии, зависимости, основные версии компонентов и способ разрешения конфликтов версий.

При локальной сборке инструмент Brazil представляет конфигурацию в виде ориентированного ациклического графа (DAG). Он получает пакеты из выделенного для myservice набора версий (VersionSet) с именем myservice-cpp-version-set, формирует конфигурацию для выбранного языка и запускает соответствующий инструмент сборки, создающий выходной артефакт.

Набор версий — коллекция версий пакетов, образующая отдельное пространство для пакета и его зависимостей. При добавлении новой зависимости её также нужно включить в это пространство. Существует набор версий по умолчанию — «live»: это общее пространство, куда можно публиковать любые версии.

Для удалённых сборок используется сервис package builder: в нём выбирают набор версий и цели сборки. Сервис поддерживает Amazon Linux на платформах x86, x64 и ARM. Сборку можно запустить вручную или автоматически после нового коммита в ветку master. Package builder обеспечивает согласованность и воспроизводимость сборок: для каждого процесса сохраняется снимок, а выходной артефакт получает версию.
