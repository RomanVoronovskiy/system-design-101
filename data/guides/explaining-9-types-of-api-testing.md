![](https://assets.bytebytego.com/diagrams/0017-9-types-of-api-testing.png)

* **Тестирование дыма**
    Это делается после завершения разработки API. Просто проверьте, работают ли API и ничего не сломалось.
* **Функциональное тестирование**
    При этом создается план тестирования на основе функциональных требований и сравниваются результаты с ожидаемыми.
* **Интеграционное тестирование**
    Этот тест объединяет несколько вызовов API для выполнения сквозных тестов. Проверяются внутрисервисные коммуникации и передача данных.
* **Регрессионное тестирование**
    Этот тест гарантирует, что исправления ошибок или новые функции не нарушат существующее поведение API.
* **Нагрузочное тестирование**
    Это тестирует производительность приложений путем моделирования различных нагрузок. Затем мы можем рассчитать емкость приложения.
* **Стресс-тестирование**
    Мы намеренно создаем высокие нагрузки на API и проверяем, могут ли API нормально работать.
* **Тестирование безопасности**
    Это тестирует API на предмет всех возможных внешних угроз.
* **Тестирование пользовательского интерфейса**
    При этом проверяется взаимодействие пользовательского интерфейса с API-интерфейсами, чтобы убедиться, что данные отображаются правильно.
* **Нечеткое тестирование**
    Это вводит неверные или неожиданные входные данные в API и пытается привести к сбою API. Таким образом, он выявляет уязвимости API.
