Материал основан на инженерных блогах Uber и проектах компании с открытым исходным кодом. Если обнаружите неточности, сообщите авторам. Ссылки на источники приведены в комментариях к оригинальной публикации.

**Веб-фронтенд:** Uber разработала Fusion.js — современную платформу на основе React для создания надёжных веб-приложений. Для геопространственной визуализации используется visualization.js.

**Мобильные приложения:** кроссплатформенная архитектура RIB опирается на VIPER вместо MVC. Она поддерживает разные языки: Swift для iOS и Java для Android.

**Сервисная сеть (service mesh):** Uber Gateway реализует динамическую конфигурацию поверх NGINX. Для взаимодействия клиента и сервера используются gRPC и QUIC, для определения API — Apache Thrift.

**Серверная часть:** единое хранилище конфигурации Flipr позднее получило название UCDP. Библиотека H3 используется для геопространственной индексации. Сервисы на Java разрабатываются с помощью Spring Boot, событийная архитектура строится на uAct, а Cadence координирует асинхронные рабочие процессы.

**Базы данных:** для OLTP преимущественно используется DocStore со строгой согласованностью. В его основе — MySQL, PostgreSQL и движок хранения RocksDB.

**Большие данные:** обрабатываются средствами семейства Hadoop. В качестве форматов файлов используются Hudi и Parquet, для кеширования — Alluxio. Временные ряды хранятся в Pinot и AresDB.

**Обработка данных:** Hive, Spark и открытая платформа загрузки данных Marmaray. Для обмена сообщениями и потоковой обработки используются Apache Kafka и Apache Flink.

**DevOps:** Uber использует монорепозиторий и упрощённую среду разработки devpod. Непрерывная доставка организована через Netflix Spinnaker, метрики поступают в uMetric, оповещения обрабатывает uMonitor. M3 служит единым хранилищем данных наблюдаемости.
