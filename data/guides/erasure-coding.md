В объектных хранилищах, например S3, для повышения сохранности данных часто применяют **кодирование с исправлением стираний (Erasure Coding)**. Рассмотрим, как оно работает.

Этот подход обеспечивает сохранность данных иначе, чем репликация. Данные делятся на небольшие фрагменты, размещаемые на разных серверах, а для избыточности вычисляются контрольные блоки. При сбоях исходные данные можно восстановить по сохранившимся фрагментам и контрольным блокам. На рисунке 1 приведён пример схемы 4 + 2.

* Данные делятся на четыре фрагмента одинакового размера: d1, d2, d3 и d4.

* По математической формуле вычисляются контрольные блоки p1 и p2. Сильно упрощённый пример: p1 = d1 + 2\*d2 - d3 + 4\*d4 и p2 = -d1 + 5\*d2 + d3 - 3\*d4.

* Из-за отказов узлов теряются фрагменты d3 и d4.

* Потерянные фрагменты d3 и d4 восстанавливаются по математической формуле с использованием известных значений d1, d2, p1 и p2.

Сколько дополнительного места требует такая схема? На каждые два фрагмента данных нужен один контрольный блок, поэтому накладные расходы на хранение составляют 50% (рисунок 2). Для сравнения: при хранении трёх копий данных накладные расходы составляют 200% (рисунок 2).

Повышает ли кодирование с исправлением стираний надёжность хранения? Предположим, что вероятность отказа узла за год равна 0,81%. Согласно расчёту Backblaze, приведённому для этого примера, кодирование с исправлением стираний позволяет достичь сохранности данных на уровне «11 девяток», а репликация с тремя копиями — «6 девяток».
