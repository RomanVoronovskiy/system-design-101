* **На основе модели домена**
    При разработке структуры путей RESTful API мы можем обратиться к модели предметной области.
* **Выберите правильные методы HTTP**
    Определение нескольких основных методов HTTP может упростить разработку API. Например, PATCH часто может стать проблемой для команд.
* **Правильно реализуйте идемпотентность**
    Предварительное проектирование идемпотентности может повысить надежность API. Метод GET идемпотентен, но чтобы POST был идемпотентным, его необходимо правильно спроектировать.
* **Выберите правильные коды состояния HTTP**
    Определите ограниченное количество кодов состояния HTTP, которые будут использоваться для упрощения разработки приложений.
* **Версии**
    Заблаговременное определение номера версии API может упростить работу по обновлению.
* **Семантические пути**
    Использование семантических путей упрощает понимание API, поэтому пользователи могут найти правильные API в документации.
* **Пакетная обработка**
    Используйте пакетное/массовое ключевое слово и поместите его в конец пути.
* **Язык запроса**
    Разработка набора правил запросов делает API более гибким. Например, нумерация страниц, сортировка, фильтрация и т. д.
