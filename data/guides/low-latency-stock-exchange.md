Как современная фондовая биржа достигает **микросекундных задержек**? Основной принцип:

**Выполнять меньше работы на критическом пути.**

* Меньше задач на критическом пути.
* Меньше времени на каждую задачу.
* Меньше сетевых переходов.
* Меньше обращений к диску.

Критический путь на фондовой бирже выглядит так:

* **Начало:** заявка поступает в систему управления заявками — Order Manager.
* Выполняются обязательные проверки рисков.
* Заявка сопоставляется со встречной, и информация об исполнении отправляется обратно.
* **Конец:** результат исполнения выходит из Order Manager.

Остальные, некритичные задачи следует вынести с критического пути.

Предлагаемая архитектура показана на схеме:

* Все компоненты развёрнуты на одном мощном сервере без контейнеров.
* Для обмена событиями между компонентами используется общая память вместо жёсткого диска.
* Ключевые компоненты, например Order Manager и механизм сопоставления заявок Matching Engine, работают на критическом пути в одном потоке. Каждый закреплён за процессором, чтобы **избежать переключений контекста** и **блокировок**.
* Однопоточный цикл приложения последовательно выполняет задачи одну за другой.
* Остальные компоненты слушают шину событий и реагируют на поступающие события.
