Сначала уточним основные понятия.

* **NLB (Network Load Balancer)** обычно размещается перед API-шлюзом и маршрутизирует трафик на основе IP-адресов. HTTP-запросы он не разбирает.
* **ALB (Application Load Balancer)** маршрутизирует запросы по HTTP-заголовкам или URL, поэтому поддерживает более гибкие правила. Выбор балансировщика зависит от требований к маршрутизации. Для небольших и простых сервисов может быть достаточно одного балансировщика.
* **API-шлюз** решает задачи прикладного уровня и выполняет иные функции, чем балансировщик нагрузки.

Схема показывает детали. Эти компоненты часто используются вместе для создания масштабируемой и безопасной архитектуры веб-приложений.

**Вариант a:** ALB распределяет запросы между сервисами. Каждый сервис самостоятельно реализует ограничение частоты запросов, аутентификацию и другие функции. Этот подход гибче, но требует больше работы на уровне сервисов.

**Вариант b:** API-шлюз берёт на себя аутентификацию, ограничение частоты запросов, кеширование и подобные задачи. Сервисам остаётся меньше работы, однако этот вариант менее гибок по сравнению с использованием ALB.
